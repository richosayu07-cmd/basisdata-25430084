# 2. PENGUJIAN D.4 — SKENARIO PENGUJIAN DATABASE

## 2.1 UJ-01 — Transaksi Penjualan Anggota Aktif

**Tujuan:** Menguji apakah anggota dengan status aktif dapat melakukan transaksi penjualan.

**Perintah SQL:**

```sql
INSERT INTO penjualan
(no_nota_penjualan, tgl_penjualan, id_petugas, id_anggota, bayar_penjualan)
VALUES ('PJ-UJ01-0001', NOW(), 3, 1, 10000);
```

**Hasil pengujian:** Berhasil, satu baris data dimasukkan dengan ID penjualan 6.

**Kesimpulan:** Database menerima transaksi dengan anggota aktif, sehingga pengujian dinyatakan berhasil.

**Status: LULUS.**

## 2.2 UJ-02 — Transaksi Penjualan Tanpa Anggota

**Tujuan:** Menguji apakah transaksi penjualan dapat dilakukan tanpa menghubungkan transaksi dengan anggota.

**Perintah SQL:**

```sql
INSERT INTO penjualan
(no_nota_penjualan, tgl_penjualan, id_petugas, id_anggota, bayar_penjualan)
VALUES ('PJ-UJ02-0001', NOW(), 3, NULL, 10000);
```

**Hasil pengujian:** Berhasil, satu baris data dimasukkan dengan ID penjualan 7.

**Kesimpulan:** Database menerima transaksi dengan nilai `NULL` pada kolom `id_anggota`. Hal ini menunjukkan bahwa transaksi tanpa keanggotaan diperbolehkan oleh struktur tabel.

**Status: LULUS.**

## 2.3 UJ-03 — Pengujian CHECK pada Stok Barang

**Tujuan:** Menguji apakah database menolak nilai stok barang yang negatif.

**Perintah SQL:**

```sql
UPDATE barang
SET stok_barang = -5
WHERE id_barang = 1;
```

**Hasil pengujian:** Database menolak perintah dengan pesan:

`#4025 - CONSTRAINT ck_barang_stok failed`

**Kesimpulan:** Constraint `ck_barang_stok` berhasil mencegah perubahan stok menjadi nilai negatif.

**Status: LULUS.**

## 2.4 UJ-04 — Pengujian UNIQUE pada Nomor Nota

**Tujuan:** Menguji apakah nomor nota yang sudah digunakan dapat dimasukkan kembali.

**Perintah SQL:**

```sql
INSERT INTO penjualan
(no_nota_penjualan, tgl_penjualan, id_petugas, id_anggota, bayar_penjualan)
VALUES ('PJ-UJ01-0001', NOW(), 3, 1, 10000);
```

**Hasil pengujian:** Database menolak data dengan pesan:

`#1062 - Duplicate entry 'PJ-UJ01-0001' for key 'uq_penjualan_nota'`

**Kesimpulan:** Constraint `UNIQUE` pada nomor nota berhasil mencegah penggunaan nomor nota yang sama.

**Status: LULUS.**

## 2.5 UJ-05 — Pengujian CHECK pada Jumlah Barang

**Tujuan:** Menguji apakah jumlah barang pada detail penjualan tidak boleh bernilai nol.

**Perintah SQL:**

```sql
INSERT INTO detail_penjualan
(id_penjualan, id_barang, qty_detail_penjualan, harga_satuan_detail_penjualan)
VALUES (6, 1, 0, 3000);
```

**Hasil pengujian:** Database menolak data dengan pesan:

`#4025 - CONSTRAINT ck_detail_qty failed`

**Kesimpulan:** Constraint `ck_detail_qty` berhasil membatasi jumlah barang agar tidak menggunakan nilai nol.

**Status: LULUS.**

## 2.6 UJ-06 — Pengujian UNIQUE pada NIM Anggota

**Tujuan:** Menguji apakah NIM yang sudah terdaftar dapat digunakan kembali oleh anggota lain.

**Hasil pengujian awal:** Percobaan pertama menggunakan nomor anggota yang melebihi batas panjang kolom `CHAR(6)` dan menghasilkan pesan:

Selanjutnya dilakukan pengujian menggunakan NIM yang sudah terdaftar.

**Hasil pengujian UNIQUE:** Database menolak data dengan pesan:

**Kesimpulan:** Constraint `UNIQUE` pada NIM berhasil mencegah penggunaan NIM yang sama oleh anggota lain.

**Status: LULUS.**

## 2.7 UJ-07 — Pengujian FOREIGN KEY pada Petugas

**Tujuan:** Menguji apakah transaksi dapat menggunakan ID petugas yang tidak tersedia pada tabel petugas.

**Perintah SQL:**

```sql
INSERT INTO penjualan
(no_nota_penjualan, tgl_penjualan, id_petugas, id_anggota, bayar_penjualan)

```

**Hasil pengujian:** Database menolak data dengan pesan:

`#1452 - Cannot add or update a child row: a foreign key constraint fails`

**Kesimpulan:** Foreign Key berhasil menjaga hubungan antara tabel penjualan dan tabel petugas dengan menolak ID petugas yang tidak tersedia.

**Status: LULUS.**

## 2.8 UJ-08 — Pengujian Safe Update Mode

**Tujuan:** Menguji penerapan Safe Update Mode ketika melakukan perubahan data pada tabel barang.

**Hasil pengujian:** Percobaan UPDATE tanpa kondisi `WHERE` yang menggunakan kolom kunci ditolak oleh database dengan pesan:

`#1175 - You are using safe update mode`

**Kesimpulan:** Safe Update Mode berfungsi mencegah perubahan data secara luas tanpa kondisi yang memenuhi aturan keamanan.

**Status: LULUS.**

# 3. PENGUJIAN E — PENGARSIPAN DAN PEMBARUAN DATA

## 3.1 E.1 — Pengarsipan Anggota Nonaktif

**Tujuan:** Mengarsipkan anggota yang berstatus nonaktif dan memiliki tanggal pendaftaran sebelum tahun 2025. Anggota yang masih memiliki transaksi penjualan tidak boleh dihapus dari tabel asal.

### A. Pemeriksaan Data Anggota

Pemeriksaan dilakukan untuk mengetahui anggota yang memenuhi kriteria pengarsipan.

**Perintah SQL:**

```sql
SELECT
    id_anggota,
    no_anggota,
    nim_anggota,
    nama_anggota,
    status_anggota,
    tgl_daftar_anggota
FROM anggota
ORDER BY id_anggota;
```

**Hasil pemeriksaan:** Budi Santoso dengan ID anggota 3 memiliki status `nonaktif` dan tanggal pendaftaran `2024-08-10`. Data tersebut memenuhi kriteria pengarsipan.

### B. Pemeriksaan Riwayat Transaksi

Sebelum pengarsipan, dilakukan pemeriksaan untuk memastikan anggota tidak memiliki transaksi penjualan.

**Perintah SQL:**

```sql
SELECT
    a.id_anggota,
    a.nama_anggota,
    p.id_penjualan,
    p.no_nota_penjualan
FROM anggota AS a
LEFT JOIN penjualan AS p
    ON a.id_anggota = p.id_anggota
WHERE a.id_anggota = 3;
```

**Hasil pemeriksaan:** Kolom `id_penjualan` dan `no_nota_penjualan` menunjukkan nilai `NULL`.

**Kesimpulan:** Budi Santoso tidak memiliki transaksi penjualan sehingga memenuhi syarat untuk diarsipkan.

### C. Membuat Tabel Arsip

Tabel arsip dibuat dengan mengikuti struktur tabel anggota.

**Perintah SQL:**

```sql
CREATE TABLE IF NOT EXISTS anggota_arsip LIKE anggota;
```

**Hasil:** Perintah berhasil dijalankan tanpa menampilkan baris hasil.

### D. Menyalin Data ke Tabel Arsip

Data anggota yang memenuhi kriteria kemudian disalin ke tabel `anggota_arsip`.

**Perintah SQL:**

```sql
INSERT INTO anggota_arsip
SELECT a.*
FROM anggota AS a
WHERE a.status_anggota = 'nonaktif'
  AND a.tgl_daftar_anggota < '2025-01-01'
  AND NOT EXISTS (
      SELECT 1
      FROM penjualan AS p
      WHERE p.id_anggota = a.id_anggota
  );
```

**Hasil:** Satu baris data berhasil dimasukkan ke tabel arsip (`1 row inserted`).

### E. Memeriksa Data Arsip

**Perintah SQL:**

```sql
SELECT *
FROM anggota_arsip;
```

**Hasil:** Data Budi Santoso berhasil ditemukan di tabel `anggota_arsip` dengan ID anggota 3, nomor anggota A-1003, NIM 2501000003, status nonaktif, dan tanggal pendaftaran 2024-08-10.

### F. Menghapus Data dari Tabel Asal

Setelah data berhasil disalin dan diverifikasi, data Budi Santoso dihapus dari tabel `anggota` dengan kondisi yang memastikan data telah diarsipkan dan tidak memiliki transaksi.

**Perintah SQL:**

```sql
DELETE FROM anggota
WHERE id_anggota = 3
  AND status_anggota = 'nonaktif'
  AND tgl_daftar_anggota < '2025-01-01'
  AND EXISTS (
      SELECT 1
      FROM anggota_arsip
      WHERE id_anggota = 3
  )
  AND NOT EXISTS (
      SELECT 1
      FROM penjualan
      WHERE id_anggota = 3
  );
```

**Hasil:** Satu baris berhasil dihapus dari tabel anggota (`1 row deleted`).

### G. Verifikasi Hasil Pengarsipan

Pemeriksaan akhir dilakukan untuk memastikan data anggota tetap tersedia di tabel arsip dan anggota lainnya tidak ikut terhapus.

**Perintah SQL:**

```sql
SELECT id_anggota, nama_anggota, status_anggota
FROM anggota_arsip

UNION ALL

SELECT id_anggota, nama_anggota, status_anggota
FROM anggota
ORDER BY id_anggota;
```

**Hasil pemeriksaan:**

- Andi Saputra (ID 1) tetap berada di tabel anggota.
- Siti Rahma (ID 2) tetap berada di tabel anggota.
- Budi Santoso (ID 3) berada di tabel anggota_arsip.
- Anggota Pengujian (ID 4) tetap berada di tabel anggota.

**Kesimpulan E.1:** Pengarsipan berhasil dilakukan. Data Budi Santoso telah dipindahkan ke tabel arsip dan dihapus dari tabel asal setelah dipastikan tidak memiliki transaksi penjualan.

**Status: BERHASIL.**

## 3.2 E.2 — Pembaruan Harga Barang Kategori Makanan

**Tujuan:** Menaikkan harga seluruh barang dengan kategori makanan sebesar 5% dan membulatkan hasilnya ke ratusan terdekat.

Sebelum pembaruan harga dilakukan, struktur dan data barang diperiksa terlebih dahulu.

**Perintah SQL:**

```sql
SELECT
    id_barang,
    kode_barang,
    nama_barang,
    kategori_barang,
    harga_jual_barang
FROM barang
ORDER BY id_barang;
```

**Hasil pemeriksaan:**

| ID Barang | Nama Barang | Kategori | Harga |
|---|---|---|---:|
| 1 | Pulpen Hitam | ATK | 3000.00 |
| 8 | Buku Tulis | ATK | 5000.00 |
| 9 | Pensil 2B | ATK | 2500.00 |

Berdasarkan hasil pemeriksaan, belum terdapat barang dengan kategori `Makanan`.

### Perintah Pembaruan Harga

**Perintah SQL:**

```sql
UPDATE barang
SET harga_jual_barang = ROUND(harga_jual_barang * 1.05, -2)
WHERE kategori_barang = 'Makanan'
  AND id_barang > 0;
```

**Hasil:** Perintah berhasil dieksekusi dengan keterangan `0 rows affected`.

Pada percobaan pertama, perintah UPDATE sempat ditolak oleh Safe Update Mode dengan pesan error `#1175`. Setelah kondisi menggunakan kolom kunci `id_barang` ditambahkan, perintah berhasil dieksekusi.

**Analisis:** Tidak ada harga barang yang berubah karena belum tersedia barang dengan kategori `Makanan`. Kondisi tersebut menyebabkan tidak ada baris yang memenuhi kriteria UPDATE. Barang kategori ATK tidak ikut mengalami perubahan harga.

**Kesimpulan E.2:** Perintah pembaruan harga berhasil dieksekusi, tetapi tidak ada data yang diperbarui karena belum terdapat barang kategori makanan pada database.

**Status: PERINTAH BERHASIL DIEKSEKUSI, 0 BARIS DIPERBARUI.**
